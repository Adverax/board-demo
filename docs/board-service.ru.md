# Канбан-доска — описание на русском с пояснениями

> Это пояснительный перевод документа `board-service.md` (дизайн-бриф). Оригинал заморожен и остаётся источником истины; при расхождениях верен он.

## Что это за сервис

Небольшая канбан-доска: бэкенд на Go и одна веб-страница перед ним. Команда держит рабочие задачи в трёх колонках и двигает их вперёд.

Бриф заморожен для живой демонстрации: всё, что в нём не написано, находится вне объёма работ.

## Пользователи

| Роль | Кто это | Что делает |
|---|---|---|
| **Участник команды** | Любой, кто открыл страницу | Добавляет карточки, редактирует, переносит между колонками, удаляет |

*Пояснение:* доска одна на всех, все видят одно и то же состояние. Ролей и авторизации нет.

## Возможности

1. **Доска.** Три фиксированные колонки по порядку: `todo`, `doing`, `done`. Чтение доски возвращает все карточки, сгруппированные по колонкам, в порядке колонок.
2. **Карточки.** У карточки есть заголовок (обязателен) и необязательное описание. Новая карточка всегда попадает в конец `todo`. Заголовок и описание можно изменить, карточку можно удалить.
3. **Перенос.** Карточка переносится на одну колонку вправо или влево и попадает в конец целевой колонки.
4. **Страница.** Одна страница показывает три колонки с карточками. У каждой карточки есть кнопки «влево», «вправо», «изменить», «удалить», а на странице есть форма добавления. Если действие отклонено, причина показывается на странице.

*Пояснение:* перетаскивания мышью нет, перенос только кнопками. Это сознательно, чтобы уложиться во время.

## Правила, которые должны выполняться всегда

- **Заголовок.** После обрезки пробелов не пустой и не длиннее 80 символов.
- **WIP-лимит.** В `doing` не больше 3 карточек. Перенос в заполненную `doing` отклоняется и ничего не меняет.
- **Только соседние колонки.** Перенос `todo` → `done` напрямую (и обратно) отклоняется.
- **Плотный порядок.** В каждой колонке позиции карточек после любой операции, включая удаление и перенос, равны 0..n-1 без пропусков и дубликатов.

*Пояснение:* WIP (work in progress) — ограничение на число задач «в работе» одновременно. Именно оно даёт на демонстрации наглядный отказ в интерфейсе.

## Уже принятые решения

- Go 1.26, для HTTP стандартная библиотека `net/http`.
- Хранилище в памяти под мьютексом; при перезапуске доска теряется.
- JSON по HTTP под `/api`; ошибки — JSON-объект со стабильным полем `code` (`validation_failed`, `not_found`, `wip_limit_exceeded`, `invalid_move`).
- Эндпоинты: `GET /api/board`, `POST /api/cards`, `PATCH /api/cards/{id}`, `POST /api/cards/{id}/move` (тело `{"to": "<колонка>"}`), `DELETE /api/cards/{id}`.
- Страница на чистых HTML, CSS и JavaScript без сборки, встроена в бинарник через `go:embed` и отдаётся тем же процессом.
- Один бинарник, порт из переменной окружения `PORT` (по умолчанию 8080).
- Аутентификации нет.

## Вне объёма

- Аутентификация, пользователи, личные доски, несколько досок.
- Сохранение данных между перезапусками.
- Настраиваемые и переименуемые колонки, настраиваемый WIP-лимит.
- Drag and drop, горячие клавиши, анимации.
- Комментарии, метки, исполнители, сроки.

## Потом, не сейчас

- **Архив.** Карточки, пролежавшие в `done` дольше N дней, архивируются и скрываются с доски.
- **Drag and drop** между колонками на странице.

*Пояснение:* эти два пункта намеренно не строятся — они служат материалом для живого расширения в конце демонстрации.

## Критерии успеха первого релиза

- Бинарник запускается, отдаёт страницу, и все возможности работают от начала до конца в браузере.
- Property-тест показывает, что позиции остаются плотными после любой случайной последовательности операций добавления, переноса, изменения и удаления.
- Конкурентный тест отправляет 20 одновременных переносов в `doing`, и в колонке никогда не больше 3 карточек.
- Каждое правило выше покрыто хотя бы одним именованным тестом.
